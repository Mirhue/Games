# Kingpin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the single-player browser game "Kingpin" described in the spec. You rise from street rat to Godfather through missions, skills, weapons, a vault, investments, and fights with rivals, while dodging the police.

**Architecture:** Static ES-module site with no build step. `js/data.js` holds every number. `js/engine.js` holds the pure rules, with `rng` and `now` passed in. `js/state.js` handles saving and migration. `js/ui.js` and `js/main.js` handle the DOM and the game loop. Tests use `node --test`, and pacing is measured by `tools/sim.js`.

**Tech Stack:** HTML5, CSS3, vanilla JS (ES2022 modules), Node 22 (tests and simulation only, at `~/.local/bin/node`).

**Spec:** `docs/superpowers/specs/2026-10-10-kingpin-design.md`

## Global Constraints

- No runtime dependencies, no build step, no npm packages. The game runs from `python3 -m http.server 8766`.
- The engine never calls `Math.random`, `Date.now`, or the DOM. Every engine function takes `rng` and/or `now` as parameters.
- Engine actions return `{ ok: boolean, state, events: Event[] , reason?: string }`, where `Event = { kind: 'good'|'bad'|'info', text: string }`. The input state is never changed in place; actions work on a `structuredClone`.
- All tuning numbers live in `js/data.js`.
- All UI text is in English.
- The localStorage key is `kingpin.save`, and every save has a `version` integer.
- Success chance is always clamped to [0.05, 0.95].
- Offline investment income and vault interest are capped at 2 h (`OFFLINE_CAP_MS = 7_200_000`).

## Review Focus

1. **A corrupt or old save in localStorage** should start a new game (with a log note) instead of a blank page. Test: `load()` with invalid JSON returns `null`, and `migrate()` fills in missing fields.
2. **Clock going backwards or a huge elapsed time:** a negative `elapsed` is treated as 0, and huge values don't overflow. Test: `tick(state, now - 1000)` doesn't change anything, and `applyOffline` with 30 days still caps income at 2 h.
3. **Fast double-clicks on a mission:** you must never spend nerve below 0 or act while in jail. Test: an action with not enough nerve returns `ok:false` and leaves the state unchanged.
4. **Vault overflow or depositing more than you have:** the deposit is limited by both your cash and the vault's free space, the fee is applied, and interest never goes above capacity. Tests are in Task 6.
5. **Floating-point money drift:** cash is always rounded to whole dollars after every change. Test: after 1000 random missions in the simulation, cash is still an integer.

### Task 10: Balance simulation + tuning

**Files:** `tools/sim.js`, `js/data.js`.

The bot works on 1-second steps of simulated active play:
- It runs the mission with the best expected value per nerve when it has enough nerve.
- It buys the cheapest affordable upgrade in this order: skill → weapon → investment (if it pays back within 30 min) → vault.
- It banks cash above 2 minutes of earnings, bribes when heat is over 60, pays bail if bail costs less than 30 s of income, and attacks rivals when its win chance is over 60%.

It reports the time each rank was reached, the time of the win, and the longest gap between purchases.
